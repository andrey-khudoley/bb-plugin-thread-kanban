## Agent inspection and MCP

Use «Создать проект» beside the project selector to create a native BB project, including from an empty or filtered board. On narrow screens it is a folder-plus icon with the same accessible name. Enter a name, select a connected computer and supply the full path to an existing folder on that computer. Creation, cancellation and errors preserve the board selection and all filters. The new project is added immediately; only the explicit «Показать проект» action in the success notification selects it and clears card filters. The form uses the signed-in user's public BB API and blocks repeated submission while saving.

Use the plugin's native tools while changing or diagnosing Kanban. Prefer `kanban_snapshot` for server data, `kanban_card_get` for a task or native chat (`kind: "thread"`), and `kanban_diagnostics` to confirm the installed revision, frontend bundle hash and deployment. Server data does not establish that the UI rendered it.

Use `kanban_ui_snapshot` for a fresh report from the actual BB frontend: filters, collapsed stages, selection, rendered card IDs and bounds, visible controls, open panels/menus and frontend errors. `inViewport` accounts for clipping by scroll containers. A rendered card may be outside the viewport. Select a particular `windowId` when several windows are present. `board_closed` means a frontend replied without an open board/panel; `no_window` means no matching live response. Cached last-seen windows are diagnostic only. Reports include the frontend generation and capture time. Inspect `state[].loading` and errors before judging results.

For an actual image, run `bb browser instances --host <hostId> --json`, then `kanban_ui_open({ hostId, instanceId })`. It opens a separate observer tab of the real installed BB app and returns `windowId`. Use `kanban_ui_capture({ windowId })` to receive a JPEG, then `kanban_ui_close({ windowId })`. The observer's filters belong to its own browser window; do not describe them as the user's original window. Native tools fill the invoking thread ID. The MCP adapter outside a BB thread needs an explicit `threadId` for open. Desktop capture works on Windows and does not require DevBrowser, computer-use, or a Chrome installation. An open BB desktop instance is required. For a desktop on another machine, configure BB's app URL so that machine can reach the server.

These tools inspect data and UI; they do not move cards, start agents, mark work reviewed or merge Git. Existing mutation RPCs retain their normal behavior. Observer tabs are plugin-owned, limited to eight, expire after 30 minutes, and close on plugin disposal. Close them explicitly after use. Do not capture a user's arbitrary browser tab.

External MCP clients use `node <plugin-folder>/mcp.mjs` over stdio. Set `KANBAN_BB_CLI` to an absolute BB executable or the Node `bb` file beside `bb.cmd` if it is not on PATH; set `KANBAN_PLUGIN_ID` only for an isolated QA plugin. The adapter uses the same input schemas and validated RPCs as the native tools. It opens no network listener and writes no credentials into its configuration. Full setup and smoke-test commands are in the plugin README.

Open Канбан in BB's left navigation. Use + Задача beside the project name to create an issue in Бэклог or К выполнению independently of a BB thread. Use Задача → Уточнение to ask Codex for a title and plan, then edit them or run the work explicitly. Each issue can have a parent, dependencies, labels, a priority, an assignee, and multiple linked workspaces. Move issues by drag and drop or in the issue editor. Click the issue card or its title to open Чат for its latest linked thread or Описание for an issue without a thread. Switch among Чат, Задача and Изменения within the card. Find terminal, preview and chat branch actions under Инструменты. For native chat cards, Ветка, Форк and Вложить use BB's thread hierarchy. Archived and hidden threads are opt-in on the board.

Use the native top + to open a new tab, then click a Kanban card to fill it. Clicking another card replaces the current tab; other explicitly opened tabs stay intact. There is no duplicate new-tab button inside the card. Tab labels follow the current card title, including replacement and rename. Native tab appearance, selection, closing, dragging, splitting into panes, resizing and maximizing remain available. Chats in open tabs have a soft shadow on their cards, including inactive tabs and panes; card settings alone do not count. The actually selected native chat tab has a slightly stronger background and inner border in the same theme color. Switching, replacing or closing tabs updates this accent immediately; files, empty tabs and task settings have no active-chat accent. UI snapshots expose both `chatOpen` and `chatActive`.

Настройки BB → Настройки канбана → Открываемые окна selects right/below/above placement for subsequent Kanban openings. In a stacked layout the upper agent activity footer is always hidden and the lower footer remains visible. Use the separate Верхняя / Нижняя controls at the divider to hide or show each physical pane's header; these states persist locally. The settings independently place each pane's header in a scrollable right sidebar. Defaults: upper header above its content, lower header on the right. Header placement persists on the server and applies on the next opening. Switching back to right placement restores native headers/footers. Verify real pointer clicks, both orientations and narrow layouts; scoped CSS positions existing native controls without reparenting React-owned nodes.

Use the project heading's … menu to rename a project or move it one position up/down. Manual order is shared and persisted by the Kanban server. Убрать проект… checks all chats, including archived and hidden. If any exist, its tasks and chats appear in Personal on the board while retaining their native project, links, and environments. Restore the original group with Personal → Вернуть проект в канбан…. If there are no chats, confirm native project deletion; existing task cards are preserved in Personal. The server rechecks the current project before performing the confirmed action. Cancelling changes nothing. No BB core modifications or native chat transfers are used.


The Материалы row below the native main tabs lists the current main tab's browsers, files, terminals and other supported native artifacts. It is absent without materials. Equal captions in one pane remain separate materials, selected and closed by their live SDK keys, with numbered labels. Click Материалы to expand the searchable list below the row; it takes layout space and moves native browser content down rather than overlaying it. Click again, select a material or press Escape to close it. The mouse wheel and horizontal trackpad gestures scroll the tab strip; Ctrl + wheel keeps zooming, and the expanded list keeps its own vertical scrolling. Arrow keys, Home and End select tabs; Delete closes the selected artifact. Чат or Карточка returns to the main content. Closing the selected artifact chooses its neighbour; closing the last hides the row. Main tabs and replacement cards retain independent selections during the app session.

Files still use BB's native editors and belong to the card, including its chat and settings. Switching cards parks editors without closing their buffers; returning restores the selected file. The plugin stores card file membership and main contexts in browser storage and retains unsaved card fields and chat notes. BB owns rendering, buffers and close protection. Ambiguous native tab names stay accessible in the original strip instead of guessing their identity. BB can reuse one file editor in another section; independent copies of that editor require core support. Full application restart follows BB's own editor recovery guarantees.

Agent-created browser sessions, including existing hidden tabs, are discovered on the desktop and execution hosts through the public experimental_desktopBrowsers API. Selecting one renders the existing BrowserView by ID with existingOnly, preserving its page and automation lease across main-tab switches. Opening a browser material never acquires or revokes agent control. Перехватить explicitly returns control to the user. Browser content requires the desktop window owning that session; the web client and another desktop window show an explanation without creating a duplicate. SDK 0.6.132 has no BrowserView renderer or pane-ownership API, so the plugin isolates its capability-checked desktop bridge and decorates native chrome with a separate portal. Verify actual pages after BB upgrades, not just the tab list or presentation flag.

Use Изменения → Вся работа to see the task diff. In a shared checkout such as main, Kanban uses saved chat patches and Git commits attributed to that chat. Рабочая копия shows the current checkout, including changes outside the card.

New chats from Запуск read the saved integrated Kanban model, reasoning effort and speed at launch time. Уровень усилия and Скорость offer supported per-launch overrides; Из настроек канбана keeps inheritance. Successful launches reset the overrides. Unsupported selections show an explanation and block launch rather than silently falling back. Forks retain the source chat's execution settings.

Use Проверено on Изменения for a card in На проверке. In a shared checkout, Kanban commits the attributable changes separately and preserves unrelated staged and unstaged changes. If the task's changes are already in Git, the card can finish while other work remains in the checkout. Kanban also checks the card's other linked workspaces before setting Завершён. Kanban commits use a short `prefix: title` subject followed by a bullet for each included file.

If the check cannot establish ownership, it opens a Codex recovery chat. Use Открыть разбор правок below the error in Изменения. Answer the question in that chat if a file or fragment needs attribution. The helper repeats the same check with the confirmed scope. If HEAD, the index, or the working copy changes during the review, press Проверено again to get a fresh snapshot.

Click a column header to collapse that stage across the board. Its compact header shows its position and total filtered card count. Each project row shows a vertical stage label and its own count and still accepts drops. Click the header or a project count to expand. On narrow surfaces, pick one stage in the horizontal stage selector, or use Список for all stages. Collapse preferences are local to the browser. Task details are grouped in Обзор, Чат, Связи, and Запуски.

In a card menu, use Породить задачу to describe a single new task, or Сделать декомпозицию to generate several. The optional Уточнение field limits decomposition to a stage or part of the task. Generated cards include a plan, launch prompt, and selected source excerpts. They appear under the source in Открыть ветку задачи. Expand or collapse branches and use the breadcrumbs to navigate nested tasks. When the source is a native chat, the board links it to the parent issue. The original conversation remains accessible through the workspace and the native chat branch.

The footer on the board or card where you started shows the current stage. Click it to see all runs, agent messages, and results. Close the activity panel to continue using the board or card while the agent works. Open a generated title to focus it in the task tree, or use Открыть дерево to see all children under their source.

Mark cards created solely to test the Kanban UI or workflow with the yellow Test tag. In the derivation dialog, select the Test checkbox to tag every generated card. When creating test cards through plugin RPC, pass `test: true` to `issueCreate` or `deriveTasks`.

Use Удалить карточку in a task's menu on the board, in the tree, or in the side panel. Confirm deletion of the task and its linked chats. BB removes managed worktrees that those chats used exclusively. The dialog shows a warning and a Подтвердить button when a worktree has uncommitted changes, has commits outside main, has no commits of its own, or Git status could not be verified. Subtasks remain available. Move any child chat belonging outside the task to another branch before deleting the task. Удалить чат opens BB's own deletion confirmation for standalone chats.

Use Архивировать чат in a completed chat's menu. An issue card is hidden from the board once all its linked chats are archived. In Фильтры, turn on Показывать архивные чаты to see archived cards in their stages and use Разархивировать чат. Use Открыть ветку чата from a chat card or Ветка чата from its workspace to open the complete descendant tree, including archived chats. Use the child chat's menu to focus on its subtree, use the breadcrumb to move back up, or click a chat row to open it while keeping the tree visible.

Use Слить в main from Изменения to merge a single committed worktree. Open Слияния in the board header and use Слить готовые to plan a merge for На проверке and Завершён. The project selector scopes the plan and starts with the board's project filter. Select cards with checkboxes or Ctrl-click and use Слить выбранные for a custom batch. A planning agent orders multiple branches from task relationships and changed paths. The Слияния tab shows the plan, automatic conflict resolutions, and questions with an explanation for each choice. Use Уточнить пояснения when a saved plan needs more detail. It refreshes the explanations while preserving the choices and prior answers. A repository batch runs in a temporary worktree and waits for answers before advancing main. Git requires a clean checked-out main and clean source worktrees. The Worktree badge identifies branches with work outside main, and В main identifies integrated branches.

Settings are part of thread-kanban. Use its discoverable RPC read/save, readWindowPlacement/saveWindowPlacement and readPaneHeaders/savePaneHeaders. No separate chat-defaults plugin is needed after one-time migration. The optional workspace-deploy controller is not needed for normal installation or updates.
