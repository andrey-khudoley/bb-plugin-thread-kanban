# Разделы и проекты

Иерархия канбана: **раздел → проект (необязательно) → карточка → чаты**.

Раздел — прежний native BB project. Его ID, рабочие папки, настройки, окружения,
история и ссылки не меняются. Внешний SDK и совместимые RPC продолжают использовать
имя `projectId`. Переименование касается пользовательских надписей канбана.

Проект — самостоятельная папка в хранилище канбана, с `sectionId`, названием,
материалами, собственным помощником и журналом активного времени. Карточка хранит
необязательный `folderId`; отсутствие поля в старом JSON читается как `null`.
Карточка без проекта остаётся непосредственно в разделе. Нативные чаты без карточки
сохраняют прежнее поведение; команда «Создать карточку для этого чата» позволяет
затем выбрать проект в описании карточки.

## Пользовательский сценарий

- «Создать» у раздела открывает выбор «Задача / Проект-папка».
- Нажатие заголовка проекта сворачивает или разворачивает вложенные карточки.
  Состояние раскрытия сохраняется отдельно для каждого окна браузера.
- Меню «Действия с проектом» открывает сразу выбранную вкладку: «Помощник»,
  «Материалы» или «Карточки». Меню не меняет состояние раскрытия.
- Счётчик показывает количество видимых карточек; если оно отличается от общего,
  отображается «видно / всего». Подсказка уточняет этап и общее количество.
  Рядом находятся состояние проекта и краткое активное время; точное время
  до секунд доступно в подсказке, для экранного диктора и в окне проекта.
- Вложенные карточки используют ту же ширину, типографику и компоненты, что и
  самостоятельные. Проект не добавляет боковых отступов и отдельной прокрутки.
  Шапка — плоский заголовок группы без внешней рамки и подложки. Её шрифт
  задан только для названия и сводки, без наследования карточками. Колонка доски
  не сужается ниже 16,5 rem (264 px при базовом размере 16 px); в разделённом
  окне этапы прокручиваются общей горизонтальной прокруткой доски. На узких
  экранах сохраняется существующее переключение одного этапа.
  Пустая группа объясняет, как добавить карточку; отсутствие совпадений по
  фильтрам отображается отдельно. При перетаскивании подсвечивается вся группа,
  включая свёрнутую, а отмена перетаскивания снимает подсветку.
- Во вкладке «Карточки» можно создать задачу внутри проекта, распределить существующие
  карточки по проектам того же раздела или выбрать «Без проекта · в разделе».
  Такой же выбор доступен в описании самой задачи. Перетаскивание задачи на папку
  добавляет её в проект. Оно сохраняет текущий этап карточки.
- «Удалить проект…» во вкладке «Карточки» удаляет папку, общие материалы и диалог
  помощника. Все карточки остаются непосредственно в разделе, в своих прежних
  этапах и порядке, с теми же чатами, историей и рабочими окружениями. Перед
  удалением интерфейс показывает последствия и просит подтвердить действие.
- Название, теги, приоритет, исполнитель и прочие фильтры продолжают применяться
  к вложенным карточкам. Счётчики этапов считают карточки, а не папки.
- В каждом этапе доски проект группирует свои карточки в одну папку. Например,
  три карточки «В работе» и две «На проверке» образуют две папки того же проекта:
  первая содержит три карточки, вторая две. Рядом они не дублируются. Материалы,
  состояние и таймер проекта общие; раскрытие каждой группы независимо.
  Пустая папка отображается в «Бэклоге». В списке проект объединяет все свои этапы.

## Взаимодействия с карточками

Внешнее оформление групп и карточек одинаково в обычном состоянии. Во время
перетаскивания показываются назначение, место вставки и область «Без проекта».
Недопустимый перенос в другой раздел обозначается отдельно и ничего не меняет.

| Куда перенесена карточка | Результат |
| --- | --- |
| Шапка или свободная область проекта на доске, включая пустой проект | Добавление в проект с сохранением этапа; карточка показывается в группе проекта на своём этапе |
| Карточка внутри проекта на доске | Добавление в её проект с сохранением этапа; на том же этапе — вставка перед ней, на другом — в конец проекта |
| Свободное место колонки или самостоятельная карточка на доске | Смена этапа с сохранением проекта |
| Область «Без проекта» | Извлечение из проекта с сохранением этапа |
| Заголовок этапа, включая свёрнутый | Смена этапа с сохранением проекта; группа назначения раскрывается |
| Проект или его карточка в списке | Смена проекта и порядка с сохранением этапа; список не изображает отдельную колонку этапа |
| Самостоятельная карточка в списке | Перестановка самостоятельных карточек; для извлечения участника проекта используется явная область «Без проекта» |
| Область «Без проекта» в списке | Извлечение с сохранением этапа |

После ручной перестановки включается порядок «Вручную», чтобы сортировка по
активности не отменяла видимый результат. Бросок на себя и повторный бросок
последней карточки в конец группы не изменяют данные. Escape отменяет начатое
перетаскивание. Случайный click после drag не открывает карточку.

Проект и этап независимы. Пустой проект показывается в «Бэклоге» только как
место для добавления: этот этап не назначается его новым участникам. После
добавления группа раскрывается на сохранённом этапе карточки и прокручивается
в видимую область. Подсказка при переносе объясняет, какое значение сохранится.

В меню карточки первыми расположены открытие, «Переместить…» и, у участника
проекта, «Убрать из проекта». Диалог переноса позволяет одновременно выбрать
проект и этап либо сохранить текущие значения. Те же действия доступны для
нескольких выбранных карточек через «Проект и этап…». Смена проекта ограничена
одним разделом; массовая смена только этапа сохраняет каждый исходный раздел.

Меню проекта содержит создание карточки, добавление существующих, помощника,
материалы, состав, переименование и удаление. Нажатие счётчика открывает состав,
нажатие названия только сворачивает группу. Создание из «Бэклога» оставляет
новую карточку там; из остальных этапов новая работа создаётся «К выполнению».
Ошибка создания сохраняет диалог для повторной попытки.

В составе отдельно показаны участники и поиск карточек для добавления. Можно
выбрать несколько, добавить их с сохранением этапов, поменять этап участника,
открыть карточку или перенести её. Поиск, выбор и режим сохраняются между
вкладками окна проекта. Настройки имени и удаление вынесены в отдельный блок;
одноимённые команды меню сразу показывают нужный элемент. Удаление сохраняет
все карточки и требует отдельного подтверждения последствий.

Для самостоятельного чата меню «Добавить в проект…» явно создаёт связанную
карточку, сохраняя этап и существующий диалог. Оно не запускает нового агента.
Чаты без карточки не маскируются под перетаскиваемые задачи.

Вкладки проекта поддерживают стрелки, Home и End. После отмены диалога фокус
возвращается к вызвавшему его действию; после переноса — к доступной карточке
или оставшемуся управлению. При открытии карточки фокус остаётся её окну.

Переносы выполняются через `folderRelocate`: до 200 карточек с проверкой версий,
проект, этап и позиция фиксируются одной транзакцией. Ответ содержит токен
`folderUndoMove`. Отмена доступна из уведомления, а в окне проекта — также
отдельной кнопкой в самом окне, в течение 60 секунд. Она восстанавливает
принадлежность, этап и порядок только если затронутые карточки не менялись.
Конфликт, удалённый исходный проект или истёкшее время не приводят к частичной
отмене. Токены ограничены 50 последними переносами и живут до перезапуска
плагина. Старый `folderAssign` сохранён для совместимости.

## Активное время

Сервер сохраняет `elapsedMs` (накопленное время) и `activeSince` (начало текущего
активного периода или `null`). Период активен, пока хотя бы одна карточка имеет
статус, отличный от `done`. В том числе «Отменён» не равен «Завершён».

Пустой проект и проект только с завершёнными карточками не запускают таймер.
Завершение всех, перенос или удаление последней активной карточки приостанавливают
его. Возврат карточки из завершённых или новая активная карточка возобновляют отсчёт.
Время между этими событиями учитывается и при закрытом приложении.

Запись статуса/принадлежности и переход часов выполняются в одной транзакции SQLite.
Отображение дней, часов, минут и секунд использует общий секундный таймер канбана;
он обновляет только индикаторы и не вызывает RPC. Сворачивание, чаты и агенты
не участвуют в расчёте.

## Материалы и RAG

Поддерживаются заметки и текстовые файлы UTF-8: TXT, MD, CSV, JSON, HTML/HTM.
Лимиты: 1 МБ на материал, 100 материалов и 10 МБ текста на проект. PDF, DOCX,
сканы, внешние URL и браузерные вкладки автоматически не извлекаются. Их текст
можно подготовить и сохранить заметкой. Браузерные материалы карточек остаются
отдельной функцией и не меняют свою принадлежность.

Сохранение ставит материал в `processing`; очередь извлекает текст, проверяет JSON,
убирает HTML-разметку, script/style и разбивает текст на фрагменты по 1600 символов
с перекрытием 200 символов. SQLite FTS5 (`unicode61`, BM25) возвращает до шести
релевантных фрагментов с ID источника, названием, версией и номером фрагмента.
Это лексический RAG: он использует слова и их префиксы, без внешних embedding API.
Поиск по смысловым синонимам без общих слов не гарантируется.

Старая версия удаляется из индекса в транзакции сохранения, до запуска извлечения.
Ошибка извлечения видна в интерфейсе; старые фрагменты не используются как запасной
результат. Исправление и повторное сохранение индексирует новую версию. Удаление
материала удаляет фрагменты в той же транзакции. После перезапуска продолжается
обработка материалов со статусом `processing`.

Помощник проекта и помощник задачи получают найденные фрагменты в запросе.
Рабочий агент получает их при запуске и инструмент `kanban_project_search` для
актуального поиска. Его параметры не принимают ID проекта: сервер определяет
доступ по текущей карточке вызывающего чата или сохранённому запуску помощника.
После переноса карточки последующие запросы используют материалы нового проекта.
Уже прочитанный текст остаётся в истории чата; агенту явно указано проверять
актуальный доступ и источники, а не использовать прежние фрагменты как текущие.

Помощник проекта по прямой просьбе пользователя может подготовить Markdown-материал
и сохранить его в общий индекс. Его скрытый рабочий чат не становится карточкой
и удаляется после завершения; видимый диалог хранится в проекте.

## Совместимость и откат

Миграция добавляет таблицы `kanban_project_folders`, `kanban_project_materials` и
виртуальную FTS-таблицу `kanban_project_chunks`. Существующие таблицы и данные BB
не переименовываются и не перезаписываются. Прежние ссылки на карточки и чаты,
ключи настроек и RPC сохранены. `kanban_snapshot` дополнительно возвращает
`sections` и `projectFolders`, сохраняя прежнее поле `projects` для совместимости.

При штатном удалении пустого раздела его папки и карточки перемещаются в Personal.
Скрытие непустого раздела в Personal меняет только группировку доски.
При удалении проекта его карточки извлекаются автоматически в одной транзакции
с удалением папки и её материалов. Статусы, порядок и история карточек сохраняются.
Завершения текущей работы агентов карточек ждать не требуется; работающий помощник
самого проекта должен сначала завершить ответ.

Откат версии плагина не требует обратной миграции: новые таблицы можно сохранить.
Старая версия покажет карточки непосредственно в разделах. Перед откатом или
ручными операциями с БД следует использовать обычную резервную копию данных BB.

## Проверки

`project-folders.test.mjs` проверяет переходы часов с управляемым `Date.now`,
совместимость старых payload, сохранность связей и сообщений, оптимистическую
версию переносов, границу разделов, FTS, обновление/удаление/ошибку извлечения,
изоляцию инструмента по текущему чату и подготовку материалов помощником.
`projects-ui.test.mjs` проверяет папки, отсутствие дублей, фильтры, статусы и
создание проекта из общего элемента управления.
